# KNW-B1-EXP-005 数据断言基准纪律

**终态**：两次被现实修正的断言——①09号"全库 2,345 车系全商用车、乘用车空白"（2026-10-17 基准）被 CDD3 实测打脸（passenger 15,000，2026-10-25）；②S1 导入验证时统计"SPU 444,030"，实际是后台导入**还在跑时的中途值**，终态 823,901（与 CDD3 源库一致）。评审明确要求：今后双方数据断言均标注基准日期与库别。

**何时读**：写任何含数字的结论/文档/commit 时；引用 CDD3 侧库状态时。

**教训全文**：
1. **库是活的**：任何"全库 X 条"断言绑定时点+库别（cdd_dev ≠ 生产），跨项目引用必须写"基准：库名+日期"；CDD3 侧 28a 答复已率先示范此格式；
2. **中途值不是终值**：后台长任务（44万行 update_or_create 需十余分钟）进行中的统计数字会误导验证结论——验证一律等进程退出后查库；
3. 文档中的过时断言**不删除、加标注**（保留演进痕迹）：`［口径标注 日期：已过时，见 XX］`——09号的做法；
4. 空仓/空白类结论（"X 不存在"）尤其危险——先跑验证命令再落笔（根 CLAUDE.md"先验证再行动"纪律），CDD3 KNW-EXP-003 同款教训在本项目复现。
