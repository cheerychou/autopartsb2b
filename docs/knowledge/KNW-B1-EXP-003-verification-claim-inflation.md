# KNW-B1-EXP-003 验收声明注水

**终态**：S1 commit 写"29号验收用例全过"，评审逐条对照：5 条中 2 条不符（门控后半未实现未测、缓存失效空转——项目根本没有缓存层）、1 条语义偷换（410 实为"SPU 不存在"非"scope 越界"）；S1 还声明"INIT/DELTA 出口"而 DELTA 未实现。修复：29号文档加勘误节（逐条状态）、I4 排期漏项补录、commit 改为如实清单+显式"已知遗留"。

**何时读**：写任何 commit message / 文档 / 汇报中的"完成/验收"字样时（根 CLAUDE.md 完成声明规范的扩展）。

**教训全文**：
1. **聚合式"全过"是最容易写也最容易错的句式**——它把 N 条声明的验证成本降到 0。验收声明必须逐条带状态（✅/⚠️/❌+一句话），如 29号§七勘误节格式；
2. **"空转通过"是隐蔽的注水形态**：测试断言了"导入后能查到"，但没有断言"机制存在"（缓存层都没建）——通过的原因与声明的机制无关时，声明即为假；
3. **语义偷换比未实现更隐蔽**：410 的契约语义是"scope 越界"，实现的是"SPU 不存在"——状态码对了、语义错了，测试照样绿；
4. **git log 是追溯体系的一部分**：注水的 commit message 污染的是整个项目最自豪的资产（文档↔代码↔git 追溯），修复"声明可信"远比修 bug 贵（评审原话）。
