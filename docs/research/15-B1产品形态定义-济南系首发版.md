# B1 产品形态定义（济南系出海首发版）

> 时间：2026-10-24 ｜ 前提：委托方拟确认济南系首发（14号场景一）
> 回答的问题：产品形态是什么？是不是"中英文双语"？

## 一、直接回答：不是"中英双语"，是"一套系统、两个面向"

| 面向 | 用户 | 语言 | 逻辑 |
|---|---|---|---|
| **管理端**（后台） | 商家员工（济南系贸易商自己人） | **纯中文** | 他们的工作语言是中文、习惯管家婆式操作；v1做英文管理端只会拖慢交付、无人使用 |
| **商城端**（前台） | 海外买家（俄语区/中东/非洲的维修厂、批发商、车队） | **多语言框架 + 按首单客户的买家结构配首发语种** | 海外买家不用中文——"中英双语"里的中文在买方端是负资产 |

**为什么不是中英双语**：①中文只属于管理端；②买方端的英语只是"通用兜底语"，济南系最大的买家群（俄语区、非洲法语区、中东）各有母语——**语种是商业选择（跟随首单客户的客户结构），不是技术默认值**。

**首发语种建议**（跟首个共建客户走）：
- 客户做俄语区/中亚 → **俄语 + 英语** 双语起步（俄语区是济南系最大出口方向）；
- 客户做中东/非洲 → **英语 + 阿语**；阿拉伯语为RTL（右到左）布局，工程量约+30%，放第二波；
- 原则：**每个语种都是后卖给下一个客户的模块**（复制到中东/俄罗斯场景时的可复用资产）。

## 二、角色 × 界面 × 功能矩阵

| 角色 | 端 | 语言 | v1 功能 |
|---|---|---|---|
| 商家员工 | 管理端 Web | 中文 | 商品/库存（进销存）、询价报价、订单处理、客户与账期、适配目录维护 |
| 商家老板 | 移动端 | 中文 | 看板、审批、库存与订单速览（CDD3 移动端复用） |
| 海外买家（游客） | 商城端 | 按语种包 | **按车找件目录浏览**（引流钩子：查适配不注册）、注册 |
| 海外买家（注册） | 商城端 | 按语种包 | 询盘车（RFQ）、收报价单、下单、查订单/出运状态、对账单 |

## 三、核心交易流（v2 修正：双通道并存）

> **来源与修正说明（2026-10-24，经委托方质询修正）**：初版将交易流单一定义为"询价-报价流"，系对济南系现状（36氪调研✅：询盘→报价→线下成交）的保守复刻+设计推断，**并非现有产品调研结论**。反例：俄语区 ABCP/PartsSoft 的成熟形态即"注册买家实时看价→购物车→选仓→在线下单"，俄线上购汽配比例约55%（✅02号）——直购流是已被市场验证的进化形态。修正为双通道并存：

```
通道A｜直购流（数据就绪的SKU）：
  注册买家 → 按车找件 → 看价 → 购物车 → 下单（预付/账期额度内）
  → 水单上传核销 或 在线支付（分期决策项）
  ——ABCP/PartsSoft 已验证形态；商家为SKU配价后开启

通道B｜询价流（无价/定制/大额）：
  按车找件 → 询盘车 → 商家中文后台出多语言报价单PDF（FOB/CIF）→ 买家确认转订单
  ——36氪调研的现状形态；新商家冷启动默认通道
```

- **商家按 SKU 配置通道**：数据越完备→直购占比越高→系统价值越大（强化适配目录的战略地位）；
- **在线支付 = 分期决策项（非调研结论）**：v1 以水单+账期为主（通道B为主时成立）；若首客客群直购占比高，v1.5 评估接入——俄语区涉及 Mir/SBP 本地支付与制裁合规，中东可用 PayPal+本地网关，**逐市场决策**。

## 四、部署与租户形态

- **SaaS 多租户**（CDD3 schema 隔离架构现成）：一客一租户，共享适配目录数据层；
- **商城端部署境外节点**（香港/新加坡起步）：海外买家访问速度与数据合规；管理端国内访问同一系统；
- **后续场景复制 = 模块叠加**：中东（阿语包 + VAT 发票）→ 俄罗斯（俄语包 + Честный знак 赋码 + 1C 对接）→ 厂商版（目录方租户：品牌页 + RFQ 管理）——内核不换。

## 五、v1 范围锁定

**P0（首发五项，对应 11 号规格书）**：①按车找件适配查询目录 ②进销存 ③多语言报价→订单 ④账期/对账 ⑤移动端看板。
**明确不做**：在线支付、拼柜物流深度管理、索赔单流、整车销售、阿语 RTL（第二波）、开放平台撮合。

## 六、CDD3 组件对照（研发落点）

| 模块 | 状态 | 说明 |
|---|---|---|
| 适配查询/fitment | ✅ 复用 | data_platform 适配引擎（ZF/febi 数据已入） |
| 进销存/warehouse | ✅ 复用 | 含 fitment 联动 |
| 订单/账期 | ✅ 复用+改造 | core/orders + FIN-007 账期 PRD |
| 移动端 | ✅ 复用 | store-mobile（iOS/Android 已交付） |
| 多语言框架 | ✅ 骨架复用 | react-i18next 已接线；**商品名翻译是内容工程**——CDD3 terminology 词表已导入 febi 词，OE号+图片是国际通用"语言"，名称翻译按品类渐进 |
| **买方商城门户** | ❌ 新建 | 最大新建项：目录浏览/询盘车/报价单PDF引擎/水单核销 |
| **报价单 PDF 引擎** | ❌ 新建 | 多语言+贸易条款（FOB/CIF）模板 |

**新建工作量占比估计约 30~40%，其余复用**——回扣 09 号成本模型：首套共建（5~7折）仍显著覆盖年研发成本。

## 七、对外描述（一页纸话术底稿）

> "一套给汽配出海商用的系统：您的业务员用中文管理库存和报价；您的海外客户用自己的语言，在他的手机上**按车型查到该换哪个件**，自助询价下单。查得准，是这套系统和其他建站的本质区别——背后是结构化的车型适配数据库。"
