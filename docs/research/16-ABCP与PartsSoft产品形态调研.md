# ABCP 与 PartsSoft 产品形态调研（俄语区成熟产品对标）

> 时间：2026-10-24 ｜ 定位：委托方指定补充调研——B1"直购流"的两个成熟产品实证
> 证据：两产品官网原文抓取 ✅ + ABCP 文档站 ✅ + PartsSoft 定价页 ✅（本文基本全部 ✅ 级）

## 一、总览对比

| 维度 | ABCP | PartsSoft |
|---|---|---|
| 运营方 | NodaSoft | PartsSoft 团队 |
| 历史 | **21+ 年** | 15+ 年 |
| 规模 | **2,900+ 汽配商店、1,100+ 接入供应商** | 客户数未公开（自称第二梯队口碑领先） |
| 定位 | "汽配网店第一平台"——**IT 产品生态**（商店+1C比价采购+目录+交叉号库+VIN人工外包） | 交钥匙网店平台——"**1 天上线**"（商店+批发+仓库+CRM+财务） |
| 收费模式 | 基础档免费、**按流水抽佣**，高档固定订阅（◻️ 官网口径待核） | 固定订阅：Старт 10,250₽/月、Магазин 12,750₽/月、Сеть 14,500₽/月 + 一次性实施 36,000₽（✅定价页） |
| 试用 | 30 天 | 14 天 |

## 二、ABCP 产品解剖（✅ 官网原文）

### 2.1 产品矩阵（六件套）
1. **Интернет-магазин（在线商店）**：交钥匙汽配网店——供应商与目录接入、仓库与财务、marketplace 集成、1C 集成；
2. **Проценка ABCP в 1С（1C 内比价采购）**：**不离开 1C** 即可向 1,100+ 供应商比价、下单——尊重在位工作流的接入策略；
3. **Программа для магазина（门店管理程序）**：不需要建网站也能用全部 ABCP 功能（记账→采购）；
4. **Кроссы ABCP（交叉号知识库）**：**每日更新**的配件知识库（来自制造商）——OE↔副厂交叉号的持续供给机制；
5. **Каталоги ABCP（类目目录）**：**103+ 个持续更新的品类目录，含图片与参数**；
6. **VINQU（VIN 人工代查外包）**：客户提交 VIN，**人工选件，平均处理时间 5 分钟**。

### 2.2 周边能力（文档站 ✅）
- **多语言/本地化**（多 locale 管理、按 URL/图标切换、内容按 locale 填写）；
- 表单体系：批发/零售双注册、**汽修厂工单预约**（резервирование работ для автосервиса）、员工代客下单、退货申请；
- 数据合规文档覆盖 **俄罗斯/白俄罗斯/哈萨克斯坦三国**（242-FZ 类要求）——跨境部署先例。

## 三、PartsSoft 产品解剖（✅ 官网原文）

### 3.1 功能全景（11 项）
1. **配件目录与交叉号**：在线目录+交叉号库+配件图片+SEO；**接入原厂目录 Laximo、АвтоДилер（AutoDealer）、ilCats**；
2. **订单管理**：全渠道订单入口（网站客户、**Excel 文件**、marketplaces），自动处理；报价分析（проценка）与 **VIN 请求**管理；
3. SEO 工具（全站可索引，Yandex/Google）；
4. **供应商 API**：实时获取多供应商最优报价；"搜索速度取决于最慢的供应商"（诚实的工程细节）；
5. **业务扩展**：分支机构+加盟商（франчайзи）统一平台；
6. **通知**：Telegram / Email / SMS 单窗口客户沟通；
7. 销售分析报表（利润/热门料号/客户活跃）；
8. **54-ФЗ 在线收银机集成**（电子小票自动生成→税务）；
9. **Marketplace 集成**：Яндекс Маркет、Мегамаркет、Ozon、Avito、Zzap、Drom（库存同步）；
10. **1C:Бухгалтерия 自动同步**（Магазин 档起含）；
11. 开放性：客户端 API + 管理端 API + Webhooks + Swagger 文档。

### 3.2 上手三步（✅ 官网流程）
**申请试用（14天免费）→ 上传供应商价格表（прайс-листы，Excel）或 API 接入 → 开卖（自营网站+marketplaces）**。
> 注意第2步：**商家用 Excel 价格表即可启动**——这是冷启动门槛的关键设计。

## 四、共同的核心机制：俄式"按车找件 + 价格聚合"模型

两产品形态不同，但共享同一套**数据/交易骨架**——这正是"完全在线化"得以成立的三个前提：

```
买家旅程（7步）：
①选车（品牌→车型→排量/年份，或 VIN 直查）
  →②品类目录（Laximo/TecDoc 类，按车显示适配品类）
  →③交叉号展开（一个用途→原厂号+全品牌副厂件 аналог 列表）
  →④多供应商报价行（自有仓"наличие有货" vs 外部"под заказ订货"，价格+到货期）
  →⑤购物车（按报价行选择）→⑥下单（在线支付/对公/批发账期）→⑦履约（自有仓发货或供应商直发）+ 54-ФЗ 电子小票

数据基础设施（三层）：
目录层：Laximo / AutoDealer / ilCats / TecDoc 类（"按车找件"的结构）
交叉号层：Кроссы / кросс-номера 知识库（每日更新）
价格层：прайс-листы 聚合——供应商上传 Excel 价格表或 API 接入（价格+库存+到货期）
```

**B2B 要素**：批发/零售双注册、对公与账期、员工代客下单、企业客户分级价格。

## 五、对 B1 产品定义的八点映射

| # | 成熟市场机制 | 对委托方产品的含义 |
|---|---|---|
| 1 | 完全在线化的三前提=**目录层+交叉号层+结构化价格层** | CDD3 已有目录层（fitment/类目）与交叉号雏形（OE映射）；**价格层的"商家上传价格表即可开卖"机制必须在 B1 设计中**（冷启动最低门槛） |
| 2 | прайс-листы 价格表聚合（Excel上传/API双轨） | 商家冷启动不需要"录库存"——上传现有 Excel 价格表即上线（济南系 Excel 数据直接变资产） |
| 3 | **VINQU 人工代查**（5分钟/单） | 适配数据缺失 SKU 的**第三通道：人工代查**——查询即采集（每次代查沉淀一条适配数据），是冷启动期"直购+询价"之外的兜底兼数据飞轮 |
| 4 | Кроссы 每日更新知识库 | 目录不是静态表，是**持续运营的数据产品**——CDD3 数据平台的更新机制对标 |
| 5 | 接入 Laximo/AutoDealer 等第三方目录而非自建 | 印证 07号"分层采购"惯例；**但它们都不含中国车件——您的差异化=自建中国件目录，且未来可反向成为别人的"目录层"** |
| 6 | ABCP 有"汽修厂预约"产品线 | 证明"卖配件的+修车的"同生态共存在成熟市场成立——**CDD3 双端架构（门店+数据平台）与俄成熟形态一致** |
| 7 | 多语言 + 三国数据合规文档（ABCP） | 跨境多语言/多国合规在俄语区产品中已是标配能力——B1 的语言包策略（15号）有成熟先例 |
| 8 | 两种定价范式：**免费基座+流水佣金（ABCP）vs 固定订阅（PartsSoft）** | B1 定价可二选一或混合：起步按固定订阅（简单），跑通后对高流水客户提供佣金制选项 |

## 六、差异化确认（B1 ≠ ABCP 复刻）

1. **目录层差异**：ABCP/PartsSoft 依赖 Laximo/TecDoc/AutoDealer——**中国品牌车与件不在其中**；B1 的核心资产=自建中国件适配目录（08号），这是它们结构上做不了的事；
2. **市场差异**：它们是俄国内单一市场、单一币种、卢布结算；B1 = 跨境多币种/多语言/多合规（T/T 水单、账期、VAT/赋码）；
3. **一句话定位**：**B1 = ABCP 的形态成熟度 × 中国件适配目录 × 出海跨境场景**——三者交集在现有市场上不存在。
