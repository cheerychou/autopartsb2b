# B1 产品定义参考包（委托方自研定义用）

> 时间：2026-10-24 ｜ 用途：委托方已裁定**按自身需求理解定义产品、标准品销售**（不做访谈/共建）。本包把散在 06/07/09/11/14/15/16/17/18 号的外部参考集中为**按模块组织的对照基线**——您逐模块看"参照怎么做的"，做取舍，填"开放参数"，即完成产品定义。
> 标注体系：✅ 有实证（附来源）｜ 🟡 推断 ｜ ❓ **开放参数（需您定义）**

## 使用流程建议

```
逐模块：读"参照做法" → 对照"CDD3现状" → 定"做/不做/怎么做" → 填"开放参数"
最终产出 = 第七节的《开放参数决策表》填完 → 即为产品定义 v1.0
```

## M1 商城前台（买方门户）——最大新建项

| 参照 | 做法 |
|---|---|
| ABCP ✅ | 游客/注册买家 → 选车（品牌→车型→排量年份）或 VIN → 品类目录 → **交叉号展开（原厂号+全品牌аналог）** → 多供应商报价行（自有仓"有货"/外部"订货"，价格+到货期）→ 购物车 → 下单；批发/零售双注册；员工代客下单；退货表单 |
| PartsSoft ✅ | 同骨架；第三方目录（Laximo/AutoDealer/ilCats）；**全渠道订单入口（网站/Excel/marketplace）** |
| 福田DCMS ✅ | 经销商门户：订单提报→审核→合同→回款→交付→发票；EPC 嵌套查图册 |

- CDD3 现状：❌ 新建（最大新建项）
- B1 建议（已定）：双通道并存——直购流（SKU配价即开）+ 询价流（冷启动默认）+ VINQU式人工代查兜底（查询即采集）
- ❓ **开放参数**：
  - 游客可见深度（适配查询全开放引流？锁价格需注册？）
  - 直购通道的开启规则（商家全局开关 or 按 SKU？）
  - 买方注册审核制（B2B 防爬：按公司审核？邮箱即注册？）
  - 是否要"询价响应时限"承诺展示（ABCP 类平台的转化钩子）

## M2 适配目录 / 按车找件（差异化核心）

| 参照 | 做法 |
|---|---|
| ABCP ✅ | Кроссы 交叉号知识库**每日更新**；103+ 品类目录含图片参数；VINQU 人工代查 5 分钟/单 |
| PartsSoft ✅ | 不自建，接 Laximo/AutoDealer/ilCats；交叉号库+配件图片+VIN请求管理 |
| 福田DCMS ✅ | 配件产品信息+价格+EPC 图册嵌套 |
| PCFitment ✅ | 厂商适配数据结构化服务 $15~150/月 |

- CDD3 现状：✅ fitment 引擎 + terminology 词表（febi 已入）+ 类目树（GB44510 对齐）——**这是 B1 的差异化本体**
- ❓ **开放参数**：
  - 目录对买家的开放粒度（全开放=SEO 引擎 vs 注册可见=防同行爬）
  - 适配数据的维护责任流（厂商自助提交→平台审核？商家维护？平台运营兜底？）
  - VIN 查询是否 v1 上（VINQU 式人工代查可作数据冷启动飞轮）
  - 首批品类与品牌范围（建议：滤清器/刹车先行 × HOWO/陕汽/解放，08号）
