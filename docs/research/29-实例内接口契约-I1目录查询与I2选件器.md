## 一、定位与边界

**管**：单体应用内部，catalog 模块向 storefront（俄语商城）与 commerce（管理端交易域）提供的**只读目录查询接口**——按车找件、OE 检索、交叉号展开、类目树、SPU 详情（I1）；管理端组商品时的目录件候选检索与回填（I2）。

**不管**：I3/I4 跨境包管线（27号）；价格/库存/限时价/图片（commerce 域商品数据——catalog 只返回**关联键**）；商家自有货号检索（见§三 I1-6 的归属裁定🟡）；数据编辑（catalog 自带管理界面 F-24，不经本接口）。

**实现形态（🟡）**：SKU-B 单体交付（24号裁定5），I1/I2 实现为**模块间进程内调用**（Python service 层）；本文按 REST 资源模型书写契约（语言中性、可测试），若未来拆分应用（23号拓扑）可原样升级为内网 HTTP——**契约不变，实现可变**。

## 二、通用约定

| 项 | 约定 | 依据 |
|---|---|---|
| 路径前缀 | `/catalog/v1/...`（版本化；MAJOR 变更随包 schema 纪律，27号§六） | 🟡 |
| 方法 | **仅 GET**（只读，23号 I1"只读"裁定） | ✅ |
| 语言协商 | 请求头 `Accept-Language`（默认 `ru`）→ 按 **entity_names 回退链 ru→en→zh** 解析 display_name（27号定稿要点）；响应含 `name_chain` 供前台标注"官方名/俄市俗称" | ✅/🟡 |
| verified 门控 | 默认 `verified_only=true`（源码 `verified_only()` 语义：未验证行不对消费端可见）；管理端数据员角色可显式 `include_unverified=true`（详情见§六） | ✅/🟡 |
| 缓存 | 服务端缓存键 = `catalog_version（=pack_id，27号§七.6）+ locale + verified_gate + 查询参数`；包导入成功后 catalog_version 变更即整体失效 | ✅（23号 I1） |
| 分页 | `page`/`page_size`（默认 20，上限 100🟡）；响应带 `total` | 🟡 |
| 响应包络 | `{ data, meta: { total, page, catalog_version, locale } }`；错误 `{ error: { code, message } }` | 🟡 |
| 错误码 | 400 参数校验；404 资源不存在；**410 品类包范围外**（scope 越界，27号§八）；500 内部 | 🟡 |

## 三、I1 目录查询接口（消费方：storefront 前台 + commerce 管理端）

**I1-1 品牌列表** `GET /catalog/v1/brands`（找件入口；按 brand_letter/排序返回，含 ru 显示名）
**I1-2 车系列表** `GET /catalog/v1/brands/{brand_id}/series`
**I1-3 车型列表** `GET /catalog/v1/series/{series_id}/models`（返回 model_id、ru 名、年款区间、配置摘要串：排量/变速箱/驱动）
**I1-4 按车找件** `GET /catalog/v1/fitments?model_id=&category_id=&position=&q=&page=`
- 响应 = SpuCard 列表 + 每件的本车型适配摘要（qualifiers 的人读化，如"2.0T/前制动"）——对应 F-02 的"品牌→车型→品类→适配件列表"；
- category_id 可选：缺省=该车型全部适配品类（前台先展示品类聚合🟡）；
**I1-5 类目树** `GET /catalog/v1/categories/tree`（scope 内后台类目树，node_type=leaf 为商品挂载点；俄语名走回退链）
**I1-6 OE 检索** `GET /catalog/v1/search/oe?q=`
- 输入 OE 号（规范化：去空格/连字符/大小写不敏感🟡），命中 SPU（含 oe_number 精确匹配 + 交叉号命中两类结果，分组返回）；
- **归属裁定（🟡）**：商家**自有货号**是 commerce 可售 SKU 属性（B 类数据），不经本接口——商城统一搜索框由 storefront 聚合"I1-6 OE 检索（catalog）+ 货号检索（commerce 自有查询）"两路结果；
**I1-7 交叉号展开** `GET /catalog/v1/spus/{spu_id}/interchanges`（SPUInterchange 行：目标 SPU+互换类型+方向，对应 F-04"一个 OE → 多货号列表"）
**I1-8 SPU 详情** `GET /catalog/v1/spus/{spu_id}`（含属性值 SPUAttributeValue、适配车型摘要、GTIN/HS 码、verified 标签、限时价**关联键** spu_id——价格本身由 commerce 提供）
**I1-9 VIN 直查（P1 预留）** `GET /catalog/v1/vin/decode?vin=`（26号 F-02 P1；models_vin_cache 保留拷贝，Q8）

## 四、I2 选件器接口（消费方：commerce 管理端 F-10 商品管理）

**I2-1 候选检索** `GET /catalog/v1/picker/candidates?model_id=｜oe=｜category_id=｜q=`
- 宽松匹配（多条件可组合），返回 SpuCard + 可售组装所需字段（oe_number、品牌、单位类属性、GTIN/HS 码——N2 赋码字典匹配用）；
- 管理端数据员可带 `include_unverified=true` 看全量（商家组商品时自行取舍质量风险，前台门控不受影响）；
**I2-2 回填契约**：commerce 的可售 SKU 持有 `catalog_spu_id`（UUID 软引用🟡，不用硬 FK——域间解耦，对齐 23号"目录 ID 引用"裁定）；回填时校验 SPU 存在且在 scope 内（410 拒绝）；SKU 的价格/库存/限时价/图片/俄语文案全部落 commerce，catalog 零写入。

## 五、响应模型（字段投影，来源 27号§5.1）

| 模型 | 字段（display_name 均为回退链解析结果） |
|---|---|
| BrandBrief | brand_id, code, display_name, letter, logo? |
| SeriesBrief | series_id, code, display_name, vehicle_class, year_from/to |
| ModelBrief | model_id, code, display_name, year_from/to, 配置摘要（engine/trans/drive 拼接） |
| CategoryNode | category_id, code, display_name, level, node_type, children[] |
| SpuCard | spu_id, code, display_name, oe_number, brand(BrandBrief), category(CategoryNode 摘要), verified_status, 关联键（供 commerce 挂价格） |
| SpuDetail | SpuCard + attributes[](attribute_code/name + value_text/display/number) + fitment_summary[] + gtin + harmonized_code + interchange_count |
| FitmentRow | fitment_id, spu(SpuCard 摘要), qualifiers_display, fitment_type, year_from/to, verified_status |
| InterchangeRow | target_spu(SpuCard 摘要), interchange_type, direction, priority |

## 六、verified 门控与缓存细则

1. 前台（storefront）：恒 verified_only（未验证适配行不可见——源码门控语义沿用）；**unverified/disputed 是否带"待核"标签展示 = 27号开放参数12**，本契约预留 `verified_status` 字段返回，展示策略由前台读配置；
2. 管理端（commerce/I2）：默认同门控；数据员角色（RBAC）可 include_unverified；
3. 缓存：I1 响应可被 storefront 整页缓存（键含 catalog_version）；包导入成功→版本号变更→缓存整体失效（26号 F-21→I1 的联动验收点）。

## 七、验收标准（并入 26号 M1"内部 alpha"判据）

1. 按车找件全链路演示：品牌→车系→车型→品类→适配件→SPU 详情→交叉号展开→（commerce）组 SKU 挂限时价——I1/I2 各端点齐备；
2. OE 检索命中分组（精确+交叉号）与规范化容错（空格/连字符/大小写）用例通过；
3. 门控用例：unverified 适配行在前台不可见、在管理端数据员可见；
4. 缓存失效用例：导入新数据包后，同参数查询返回新数据且 catalog_version 变化；
5. scope 越界用例：品类包外 SPU 请求返回 410。

## 九、开放参数（❓ 评审时拍板）

| # | 参数 | 倾向（🟡） |
|---|---|---|
| 1 | unverified 行前台展示策略（联动 27号-12） | 默认不可见；若首客要求"待核"标签，前台按 verified_status 渲染角标 |
| 2 | 自有货号检索归属 | commerce 自查、storefront 聚合两路（本文§三 I1-6） |
| 3 | OE 规范化规则 | 去空格/连字符/大小写不敏感；最小长度 4；模糊匹配 P1 |
| 4 | 分页默认值 | page_size=20，上限 100 |
| 5 | I1-4 缺省 category_id 时的返回形态 | 品类聚合计数优先（减少空列表体验） |
| 6 | catalog_spu_id 软引用 vs 硬 FK | 软引用（域解耦；完整性由回填校验保证） |
