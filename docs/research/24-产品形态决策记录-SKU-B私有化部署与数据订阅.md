# 产品形态决策记录：SKU-B 私有化部署 + 数据订阅

> 时间：2026-10-24 ｜ 性质：产品形态终局决策（承接 [21号](21-P3产品定义参考包-B1俄语区特化与聚合商城.md)/[22号](22-CDD3数据平台复用边界与集成方案.md)/[23号](23-B1-RU三应用架构-拆分边界与接口.md) 及形态讨论）
> 委托方裁定（2026-10-24）：**产品形态 = SKU-B**——系统私有化部署（单体交付客户环境，首建费），数据以订阅年费持续供给（数据包更新，导入后可完全断网运行）
> 框架共识：产品化只有两种形态（私有化部署 / SaaS 订阅），不存在混合形态；"部署的系统 + 订阅的数据"不是一个第三形态，而是**系统产品与数据产品两个销售标的**的组合（行业先例：TecDoc/Laximo 模式）

---

## 一、决策记录

| # | 决策点 | 裁定 |
|---|---|---|
| 1 | 系统形态 | **私有化部署**（否决 SaaS 订阅作为首发形态） |
| 2 | 交付单元 | **一个单体应用**（两前端 + 单体后端，内嵌目录模块），一个部署单元拉起 |
| 3 | 数据管理平台 | **不卖、不部署给客户**——降格为开发商内部生产设施（总仓），即 CDD3 `data_platform` 原身 |
| 4 | 数据供给 | **订阅年费 = 数据包更新**（版本化包：车型/适配/交叉号/类目/俄市命名映射） |
| 5 | 代码结构 | 维持 23 号三模块（storefront / commerce / catalog[派生自CDD3]），但它是**代码组织**而非交付件数 |

## 二、交付物定义（SKU-B 构成）

```
【交付给客户】
┌─────────────────────────────────────────────┐
│  商城单体应用（部署到客户的俄云账号/自有服务器）      │
│  ├ 前端① 俄语商城客户端（买家）                    │
│  ├ 前端② 中文商城管理端（运营方员工）               │
│  └ 单体后端                                       │
│     ├ 交易域：商品/订单/收单支付/库存/客户/赋码/限时价  │
│     └ 目录域：CDD3 目录模块派生（只读查询+数据包       │
│        导入+补录暂存）                              │
│  一个数据库 · 一套 docker-compose                    │
└─────────────────────────────────────────────┘
        ▲ 版本化数据包（订阅期持续下发，异步可断连）
        │ 补录回流（变更集，异步）
【不交付，开发商内部】
CDD3 数据总仓（data_platform 原身：导入/清洗/治理/俄语化加工/包构建/回流审核）
```

## 四、SKU-B 的工程纪律（部署形态带来的硬约束）

1. **断网自足**：买家全部查询走实例内目录镜像，任何在线依赖不得进入买家路径。例外只有两类本来就外联的业务功能：在线支付（SBP/卡网关）与赋码接口（Честный знак）——它们是交易功能，不是数据依赖；
2. **N 实例升级纪律**（单维护者的最大长期负担）：docker-compose 标准部署单元、数据库迁移只向前兼容、**数据包与代码版本解耦**（schema 版本号双轨）、每实例升级清单化——升级一个实例应当是"拉镜像→跑迁移→导包"三步；
3. **授权与订阅校验**：订阅状态在实例侧校验 + 离线宽限期；**不做远程锁死**（俄客户对"远程熄火"极度敏感，且断网自足纪律本身排除了它）——续费靠合同与数据包的持续价值；
4. **回流通道**：客户补录的适配/纠错以变更集异步上传总仓（与数据包同一套异步管线，可断连、可积攒）；
5. 实例遥测（匿名使用统计）仅作 P1 可选，且须客户明示同意。

## 五、数据订阅的商业条款要点（随标准销售合同落地）

1. **许可不买断**：实例内目录镜像授权使用，随有效订阅更新；
2. **补录回流授权**：客户在实例内补录的适配数据授权开发商纳入总仓、随后续数据包全网分发（换取持续更新服务）——这是"查询即采集"飞轮的法律前提（22号§七.3、23号§六.2 顺带解决）；
3. **订阅停止的后果**：已装数据继续可用、不再更新（不锁死）；
4. **初始数据包计入首建交付物**、按品类包计价（22号§六：首包 500–2,000 行全链路）。
